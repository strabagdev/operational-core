# PCORE-010 Basic Excel Import

## Scope

PCORE-010 adds basic bulk creation of records from an Excel template generated by Operational Core.

The flow is:

1. Download the template for one active entity type.
2. Complete the `.xlsx` file.
3. Upload it from that same entity record list.
4. Validate every row.
5. Import all records in a single transaction only when every row is valid.

This version creates new records only. It does not update, upsert, map columns manually, import CSV, or import relations.

## Excel Dependency

The implementation uses `exceljs` as the only Excel dependency. It is used server-side for both template generation and `.xlsx` parsing.

## Supported Fields

Templates include active fields with these types:

- `TEXT`
- `TEXTAREA`
- `EMAIL`
- `PHONE`
- `URL`
- `INTEGER`
- `DECIMAL`
- `MONEY`
- `BOOLEAN`
- `DATE`
- `DATETIME`
- `TIME`
- `SELECT`
- `MULTISELECT`
- `RELATION`

## Excluded Fields

These fields are excluded from templates and import parsing:

- `FILE`
- `IMAGE`

If an active excluded field is required, basic import is blocked because creating records without that value would violate the entity configuration.

## Template

The generated workbook contains:

- one worksheet;
- worksheet name derived from `EntityType.name` and capped to Excel's 31-character limit;
- row 1 with exact visible field names;
- empty rows after the header for user input;
- bold headers;
- autofilter on row 1;
- frozen first row;
- practical column widths.

It does not include IDs, field keys, example rows, hidden sheets, metadata, comments, instructions, or decorative formatting.

## Column Matching

Import matches columns by exact visible field name. It rejects:

- empty headers;
- duplicate headers;
- missing expected headers;
- unknown headers;
- duplicate importable field names in the entity configuration.

If the structure no longer matches the current entity fields, users must download a fresh template.

## Field Order

Columns are ordered by:

1. `EntityField.sortOrder`;
2. `EntityField.createdAt`;
3. `EntityField.id`.

The primary field is not duplicated because templates are generated directly from fields. Existing `EntityField.config.display.listOrder` values are compatibility data only and do not change Excel column order.

## Cell Formats

Empty cells are treated as absent values. Completely empty rows are ignored. Partially completed rows are validated.

Type rules:

- Text-like fields are converted to trimmed text.
- `INTEGER` accepts integer numbers or integer numeric text, and rejects decimals.
- `DECIMAL` and `MONEY` accept valid numeric values.
- `BOOLEAN` accepts `Verdadero`, `Falso`, `true`, `false`, `Sí`, `No`, `1`, and `0`.
- `DATE` accepts Excel dates or text in `YYYY-MM-DD`.
- `DATETIME` accepts Excel date/time values or ISO-style text.
- `TIME` accepts text in `HH:mm`.
- `SELECT` uses the exact visible label of an active option.
- `MULTISELECT` uses exact visible labels separated by semicolons, for example `Seguridad; Operaciones`.
- `RELATION` uses the target record `displayName`. Multiple relation values are separated by ` | `, for example `Oficina Técnica | Minería | Bodega`.

Formula cells are not executed. If a calculated simple result is present, the result is used; otherwise the file is rejected as unreadable.

## Validation

Rows are normalized into the same field input shape used by manual record creation and then passed through the existing validation helpers. The import applies:

- required;
- email and URL validation;
- min/max length;
- numeric minimum/maximum;
- regex;
- active option validation;
- relation target validation in the same contract and configured target entity type;
- default values during creation;
- unique checks.

Unique values are checked inside the file and against existing non-archived records in the same entity type.

Relation cells are rejected when the target `displayName` does not exist or matches more than one target record. Import does not create related records automatically.

## Policy

Import is all-or-nothing:

- if any row has an error, no records are created;
- if all rows are valid, confirmation re-reads and revalidates the file server-side;
- records are created inside one transaction.

## Limits

Central limits:

- maximum file size: 5 MB;
- maximum rows: 5,000;
- accepted extension: `.xlsx`.

CSV, `.xls`, and other formats are rejected.

## Persistence And Audit

Successful import creates:

- `EntityRecord`;
- `EntityValue`;
- `EntityRelation` for relation fields;
- `AuditEvent`;
- `AuditChange` entries through the same audit helpers used by manual creation.

Imported `EntityRecord` rows are created without a technical status. Any business state must come from an imported dynamic field, such as a `SELECT` field named Estado.

## Security

Every server operation validates:

- authenticated user;
- authorized contract;
- active entity type;
- fields from that entity type;
- active options from those fields;
- file extension and parseability;
- file size and row limits.

No uploaded file is stored permanently.

## Future Improvements

Potential follow-ups:

- Excel data validation/dropdown lists for relation fields when the target record count is practical for workbook limits;
- CSV import;
- manual column mapping;
- error export;
- background jobs for very large files;
- template versioning.
